# SynthPred — Molecular Synthesizability Prediction

A reproducible machine-learning pipeline that predicts how hard a molecule is to
synthesize from its SMILES string. It combines several published synthesizability
scores with learned molecular fingerprints, and—crucially—**fine-tunes the FSscore
model on pairwise human-preference data** before feeding everything into a
cross-validated regression + stacking ensemble.

This repository ships with a small **dummy dataset** (public molecules, fabricated
scores) so the entire pipeline can be run end-to-end without any private data.
Replace the dummy CSVs with your own (same format) to use it for real.

The pipeline chains six synthesizability signals:

| Signal | Source | License |
| --- | --- | --- |
| SAScore | [RDKit](https://github.com/rdkit/rdkit) | BSD-3-Clause |
| SCScore | [scscore](https://github.com/connorcoley/scscore) | MIT |
| SYBA | [syba](https://github.com/lich-uct/syba) | GPL |
| RAscore (XGB + TF) | [RAscore](https://github.com/reymond-group/RAscore) | MIT |
| FSscore (fine-tuned) | [fsscore](https://github.com/schwallergroup/fsscore) | MIT |
| CheMeleon fingerprints | [chemeleon](https://github.com/JacksonBurns/chemeleon) | MIT |

## 1. Requirements

- A Unix shell (Linux / macOS / WSL / Git Bash)
- [Conda](https://docs.conda.io/) on your `PATH`
- [Git LFS](https://git-lfs.github.com/) (one vendored model file is stored in LFS)

## 2. Setup

```bash
git lfs install
git clone <your-fork-url> synthpred
cd synthpred
git lfs pull            # fetch the LFS-tracked SYBA resource

python env_installer.py # creates all 6 conda environments
```

`env_installer.py` creates these environments:
`sascore-env`, `scscore-env`, `syba-env`, `chemprop-env`, `fsscore-env`, and
`rascore-env`.

> **Note on `rascore-env`.** RAscore pins old dependencies
> (Python 3.7, TensorFlow 2.5, scikit-learn 0.22). It is created separately by the
> installer. If TensorFlow 2.5 will not install on your machine, this is the most
> likely setup failure point—see Troubleshooting below.

## 3. Input file formats

All paths are configured in `config.json`; you do not edit any scripts.

**Training — regression targets** (`training_input_file`):

```csv
smiles,consensus_score
CCO,3.558
CC(=O)O,1.1
c1ccccc1,2.1
```

**Training — pairwise preferences for FSscore fine-tuning** (`consensus_pairs_file`):
`consensus_choice` is `A` if molecule `smiles_a` is the easier-to-synthesize of the pair, else `B`.

```csv
smiles_a,smiles_b,consensus_choice
Brc1ccccc1,NCCO,A
CCO,c1ccccc1,B
```

**Prediction — new molecules** (`prediction_input_file`):

```csv
smiles
CC(C)O
CCCCO
```

The included dummy files (`data/input/dummy_regression.csv`,
`data/output/dummy_consensus_pairs.csv`, `data/input/dummy_predict.csv`) are
regenerated by `python scripts/generate_dummy_data.py`.

## 4. Training

```bash
./run_training.sh
```

This runs two stages, both in `fsscore-env`:

1. **Fine-tune a production FSscore model** on *all* consensus pairs
   (`scripts/scoring/finetune_production_fsscore.py`). The resulting checkpoint is
   what prediction uses to score new molecules.
2. **No-leakage cross-validation** (`scripts/train_models/run_cv_pipeline.py` with
   `REG_CV_MODE=nl`). For each of the 5 CV folds it re-fine-tunes FSscore on only the
   pairs that do not involve that fold's test molecules, computes all baseline scores
   + CheMeleon fingerprints, and trains XGBoost / MLP regressors across every feature
   subset, then a Ridge stacking ensemble. This gives the honest reported R².

Outputs:

- `analysis_output/regression_cv/no_leakage/` — per-fold metrics, OOF predictions,
  `cv_summary.csv`, `cv_plot.png`.
- `models/cv_runs/<timestamp>/` — saved base models + stacking ensemble.
- `config.json` `checkpoint_dir` is updated to that run automatically.

## 5. Prediction

```bash
./run_prediction.sh
```

Scores the molecules in `prediction_input_file`, applies the trained stacking
ensemble, and writes `data/predictions/predicted_results.csv`
(`smiles, predicted_synth_score`).

## 6. Troubleshooting

- **`rascore-env` fails to build.** Try `tensorflow-cpu==2.5.0`, or relax the version
  in `env_installer.py`. The pipeline aborts if RAscore can't score, because its
  column is a required feature.
- **`git lfs pull` did nothing / SYBA errors.** Ensure `git lfs install` ran before
  cloning; the SYBA resource (`scripts/tools/syba/resources/syba4.csv.gz`) is in LFS.
- **CPU only.** Everything is configured to run on CPU; no GPU is required.

## 7. Repository layout

```
config.json                     # all input/output paths + options
run_training.sh                 # fine-tune FSscore + CV regression + stacking
run_prediction.sh               # score new molecules with the trained ensemble
env_installer.py                # creates the 6 conda environments
environments/                   # conda env specs
fsscore/                        # vendored FSscore (source + 1.4 MB base checkpoint)
scripts/
  generate_dummy_data.py        # regenerates the dummy CSVs
  scoring/                      # one runner per synthesizability tool + production FT
  fingerprints/                 # CheMeleon fingerprint generation
  train_models/run_cv_pipeline.py
  prediction/                   # prediction from a trained cv_run
  tools/                        # vendored scorers (SAScore, SCScore, SYBA, RAscore, CheMeleon)
data/                           # dummy inputs + (generated) outputs
models/                         # CheMeleon weights + (generated) cv_runs
```
